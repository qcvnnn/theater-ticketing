# Как объяснить проект на собеседовании

## Краткое описание

«Я разработала учебное приложение афиши театров на Python и PyQt5 с PostgreSQL. Пользователь выбирает показ и категорию места, оформляет и возвращает билет, оставляет отзыв. Администратор добавляет показы и просматривает билеты. При подготовке к портфолио доработала транзакции, ограничения и проверку прав; доработка выполнена с помощью AI-инструментов и проверена интеграционными тестами».

## Почему есть постановка и показ

Постановка — название, жанр, автор и описание. Показ — конкретные дата и время. Одна постановка имеет много показов. Вместимость относится к показу и категории, поэтому билет ссылается на показ, а не только на название спектакля.

## Почему недостаточно SELECT остатка

Два параллельных запроса могут одновременно увидеть одно свободное место. Поэтому триггер выполняет UPDATE с условием SoldSeats < TotalSeats. PostgreSQL блокирует изменяемую строку; второй запрос проверяет условие на актуальной версии и получает отказ. Изменение счётчика и INSERT билета входят в одну транзакцию.

## Зачем ограничения, если есть проверки Python

Python помогает показать понятную ошибку и проверить текущего пользователя. FOREIGN KEY, UNIQUE и CHECK не дают сохранить недопустимую структуру даже при ошибке приложения. Триггер защищает правило, затрагивающее несколько таблиц. Ограничения БД не заменяют авторизацию пользователя.

## Что означает возврат

Билет получает cancelled, время возврата сохраняется, счётчик уменьшается. Физического DELETE нет: история нужна для объяснения изменений. active не означает подтверждённую оплату или фактическое посещение. Если показ прошёл, интерфейс относит билет в архив по времени.

## Почему не сделан платёжный шлюз

Задача учебной версии — работа с данными и местами. В базе нет цены и платежей, поэтому нельзя рассчитывать выручку или утверждать, что реализована онлайн-оплата.

## Главные ограничения

Прямое подключение настольного клиента к БД подходит для демонстрации. Для публичного сервиса нужен API с серверными сессиями, разграничением прав и защитой от повторной отправки покупки. Нет учёта конкретного кресла, пересечений расписания и нагрузочных испытаний. Эти пункты стоит объяснять как следующие итерации, а не скрывать.
