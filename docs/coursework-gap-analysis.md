# Сопоставление курсовой и реализации

Основание: исходные Python-файлы, фактическая структура TheaterDB и предоставленная автором курсовая «АИС Афиша Московских театров». Текст курсовой не считается доказательством реализации.

| Область | Исходная версия | Версия портфолио |
|---|---|---|
| Технологии | Python/PyQt5/psycopg2; в отдельных разделах курсовой ошибочно указаны C++/QPSQL | Документация соответствует Python-коду |
| Пароли | Открытый текст и пароль БД в исходнике | PBKDF2-SHA256 и локальный .env |
| Места | SeatTypes для отображения, ShowSeats для покупки, ProductionSeats — дополнительная таблица | Один источник ShowSeats на показ/категорию |
| Возврат | DELETE билета без уменьшения SoldSeats; пользовательских триггеров в исходной public нет | Смена статуса и освобождение места одним триггером/транзакцией |
| Конкурентная покупка | SELECT остатка перед UPDATE без условной защиты | Атомарный UPDATE с условием наличия места |
| Связь театр–постановка | JOIN есть, внешнего ключа нет | Обязательный FK и RESTRICT |
| Регистрация | Пустые строки в уникальных email/телефоне | Необязательные контакты NULL; уникальный нормализованный логин |
| Показ | Несколько независимых commit; театр не сопоставлен постановке | Одна транзакция; совместная проверка постановки и театра |
| Статусы | В таблице Tickets статусов не было | active/cancelled; «показ завершён» вычисляется по времени |
| Цена и выручка | Полей цены/оплаты нет | Не добавлялись; денежные отчёты не заявляются |
| Расширенное администрирование | Описано в курсовой, в найденных исходниках отсутствует | Не реализовано; сохранён небольшой проверяемый объём |
| Состав актёров | Текст в Productions и отдельный справочник Troupe; связи актёр–постановка нет | Ограничение сохраняется и описано |

Курсовая содержит фрагменты шаблона про другой предметный домен. Они не перенесены в портфолио. Исторические документы не редактировались и не публиковались целиком.

## Перенос данных

Новая схема создаётся отдельно с вымышленными данными. Автоматического обновления TheaterDB нет. Для реального переноса потребовались бы: проверка повторяющихся логинов и категорий, устранение несогласованных счётчиков и ссылок, выбор источника вместимости, сброс старых паролей и явное согласование правил удаления. Исходная SQL-выгрузка сохранена как снимок структуры без строк таблиц.
